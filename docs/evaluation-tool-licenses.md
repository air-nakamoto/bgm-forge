## 採用時の運用

1. 開発専用の評価環境として管理し、本体・単体HTML・公開ビルドに依存を追加しない。
2. 名前・固定version/commit・取得元・ライセンス本文・依存関係・重み・参照音源・利用形態を記録。MITというラベルだけで全体の確認済み扱いにしない。
3. 評価ツールや由来コードを配布する場合、その配布物に必要な第三者表示を含める。開発専用でも表示義務は消えない。
4. 最初の比較基準は自分の生成曲・試聴採用曲。外部音源は利用権を確認してから使う。
5. 測定結果・音声・モデルキャッシュはローカル領域へ置く。公開ビルドの許可リストには追加しない。
6. 指標定義から独立実装する場合は出典を記録。コード移植時は元コードの条件に従う。

## 前の説明の訂正

自分の音声を評価ソフトで解析しただけで、その入力楽曲のライセンスが自動的にAGPL等へ変わるわけではない。「生成物のライセンス汚染」という説明は不正確だった。
組込み・派生コード・配布・ネットワーク提供に伴う義務と、入力音源の権利は分けて判断する。独立実行でも条件確認が一切不要になるわけではない。
素材がCC0であることだけで生成曲に関するあらゆる権利問題が解消するとは保証しない。本整理では既存の製品ライセンス表記は変更しない。
